# TokenTruth · 让投资者问得明白的代币尽调与沟通平台

> 面向 Monad 黑客松参赛项目 · v1.1 · 2026-10-17

---

## 一句话定位

**TokenTruth = 投资者侧的"AI 投研助手" + 项目方侧的"AI 沟通助手"**：把项目资料、代币规则、市场数据、社区信息整理成可验证的 AI 知识库，让投资者能直接问"这家公司靠什么赚钱？""我买的代币有什么权利？"，同时帮项目方持续、统一、可验证地向市场讲清楚自己。

核心金句：**让投资者问得明白，让项目方讲得清楚。**

---

## 一、项目概述

TokenTruth 是一个面向加密项目、投资者和项目方的双边平台：

- **投资者侧**：把白皮书、代币经济、解锁规则、市场数据、新闻、社区讨论整理为 AI 知识库，自然语言提问即可获得带来源、带时间、带风险等级的回答；
- **项目方侧**：把公司资料、产品文件统一为可维护的知识库，辅助生成介绍材料、视频脚本、新闻稿、FAQ，并直接回答投资者问题；
- **执行侧**：在用户授权并符合相关要求的前提下，辅助制定投资计划、跟踪价格、对接平台执行认购或交易；
- **可信层**：每次研究报告、项目方披露、风险状态变化都生成哈希并锚定到 Monad Testnet，形成可验证、可追踪、可复核的研究记录与沟通历史。

链上只保存摘要哈希、版本号、时间和状态信息；隐私资料和完整文档保留在链下存储。

## 二、解决的问题

### 1. 投资者侧的"信息过载 + 信息失序"

普通投资者研究一个加密项目时，通常要在 7~8 个来源间反复切换：官网/白皮书、代币经济模型、解锁数据、交易所行情、项目方公告、新闻报道、社区讨论、链上数据。这些信息分散、版本混乱，投资者很难判断：

- 哪些内容来自项目方、哪些来自市场、哪些只是社区观点；
- 项目资料是否被修改过，修改前后的差异是什么；
- AI 给的结论依据是什么，是否有时间戳和原始引用。

### 2. 项目方侧的"沟通成本高、口径难统一"

项目方在牛市/事件期会被投资者问数百个重复问题（代币权利、解锁时间、转账限制），需要持续输出介绍材料、视频脚本、新闻稿；不同渠道口径不一致又会引发争议；项目资料修改后缺乏"前后对比 + 变更存证"的工具。

### 3. 行业侧的"AI 投研缺乏可验证性"

目前 AI 投研普遍存在的问题：回答没有明确来源、没有时间戳、没有版本绑定，结论难以复核，发生争议时无法回溯。TokenTruth 用 Monad 锚定研究报告和披露版本，让"AI 说什么、依据何时何版本"可验证。

## 三、目标用户

### 1. 普通投资者（核心用户）

- 快速理解项目："这家公司靠什么赚钱？""我买的代币有什么权利？"
- 风险识别："这个项目当前最大的风险是什么？"
- 决策辅助："什么时候可以转让？""未来 3 个月有哪些解锁风险？"
- 变化解释："最近价格变化是因为基本面还是市场情绪？"

### 2. 高级用户 / 机构 / 研究员

- 建立并维护多个项目的资料知识库；
- 跨项目对比、跟踪披露变化；
- 生成尽调报告，保存带证据的研究结论；
- 跟踪投资计划执行情况。

### 3. 项目方（双边用户）

- 把白皮书、产品文档、公司资料统一为可维护的 AI 知识库；
- 统一对外口径，持续更新披露；
- 自动回答投资者重复问题；
- 辅助生成介绍材料、视频脚本、新闻稿、社交媒体内容；
- 项目资料修改时自动记录版本对比与变更摘要。

### 4. 监管 / 第三方研究

- 通过链上哈希验证研究结论的生成时间和依据版本；
- 在争议处理中作为可信证据。

## 四、核心功能

围绕"投资者问得明白 + 项目方讲得清楚"两个方向，TokenTruth 提供 4 大功能模块 + 3 个跨模块能力。

### 1. AI 知识库（投资者问得明白）

**资料导入**：支持导入白皮书、官网资料、公司介绍、产品文档、代币经济模型、解锁计划、官方公告、新闻内容、社区讨论、市场数据、链上数据。每条资料保留来源、采集时间、版本、原始 URL/哈希。

**自然语言问答**：用户可以直接提问——

- "这家公司靠什么赚钱？"
- "我买的代币有什么权利？"
- "什么时候可以转让？"
- "未来一年有哪些代币解锁？"
- "最近价格上涨是因为基本面变化还是市场情绪？"
- "项目方最近有没有修改过代币规则？"
- "这个项目当前最大的风险是什么？"

**答案结构**（每条答案都包含 6 个固定字段）：

| 字段 | 说明 |
|---|---|
| 结论 | 一句话直接回答 |
| 引用来源 | 资料 ID、URL、版本 |
| 信息时间 | 采集时间、发布时间 |
| 可信等级 | 项目方 / 市场 / 新闻 / 社区 / AI 推测 |
| 相关原文 | 关键句摘录 |
| 风险提示 | 该答案的潜在不确定性 |

**支持追问与多轮对话**：每次追问都保留上下文与历史引用。

### 2. 帮助用户分析（基本面+市场+社区+风险）

**自动整理项目基本面**：公司/团队、产品/商业模式、收入来源、用户与合作伙伴、融资情况、代币用途、持有人权利、解锁与增发、竞争项目、主要风险。

**市场和社区变化解释**：结合知识库 + 行情数据 + 新闻 + 社区帖子，解释

- 价格上涨/下跌原因
- 交易量异常
- 流通量变化
- 解锁前后影响
- 社区情绪变化
- 项目方新闻对市场的影响
- **基本面变化与价格变化是否一致**（核心分析维度）

**可信度分层标注**（每条解释都注明来源类型）：

- 🏛 **项目方已确认信息**（白皮书、官网、官方公告）
- 📊 **市场数据**（行情、流通量、链上）
- 📰 **新闻报道**（可追溯媒体）
- 💬 **社区观点**（论坛、社交媒体）
- 🤖 **AI 推测**（基于多源推理，明确标注）

### 3. 帮助用户跟踪和执行（投资计划 + 授权后执行）

> 重要边界：本模块所有执行动作**必须**在用户明确授权、并符合相关要求的前提下进行；TokenTruth 不做自动决策、不托管资金、不绕过平台 KYC/合规。

**投资计划辅助**：
- 用户设定关注项目、买入预算、风险偏好、跟踪周期；
- 系统根据知识库和市场数据生成建议关注点与跟踪指标；
- 计划可保存、可修改、可撤销。

**价格与动态跟踪**：
- 关注列表的价格提醒、流通量变化提醒、解锁事件提醒；
- 重大新闻/社区信号推送；
- 每日/每周项目动态摘要。

**用户授权后对接平台执行**：
- 整合第三方平台（CEX/DEX/认购平台）官方 API；
- 用户在 TokenTruth 页面授权后，可在 UI 内一键跳转/委托下单；
- 每笔操作生成执行记录，关联用户授权 ID、时间戳、项目版本；
- 交易哈希（如适用）回写到项目的事件流与用户档案。

**明确不做**（详见第八节）：自动买币/卖币、绕过用户确认的自动执行、资金托管、做市、刷量、操纵市场。

### 4. 帮助公司持续沟通（项目方讲得清楚）

**资料统一管理**：
- 项目方上传/更新白皮书、产品文档、公司介绍、FAQ；
- 每次修改生成新版本号 + 摘要哈希 + 旧版本保留可回滚；
- 系统自动与旧版本对比，输出变更摘要（新增/修改/删除内容）。

**内容辅助生成**：
- 项目介绍材料（一句话定位、产品价值、用户案例）；
- 视频脚本（开场 30 秒、产品演示、风险提示、CTA）；
- 新闻稿模板（融资、合作、上线、解锁事件等场景）；
- 社交媒体短文（X、Discord、Telegram 各风格）；
- 投资者 FAQ（根据历史提问自动归纳）。

**投资者问答直连**：
- 项目方预设常见问题答案，自动回复投资者；
- 未匹配的问题转发给项目方，回复后沉淀到知识库；
- 全部回复保留版本、时间和负责人。

**项目方仪表盘**：
- 投资者最常问的 10 个问题；
- 资料修改次数与变更摘要；
- 投资者满意度 / 待回复队列；
- 链上披露记录。

### 5. 版本变化追踪（跨模块能力）

任何项目资料更新都触发：
- 旧版本保留可回滚；
- 与上一版本自动 diff（文本/结构/关键字段）；
- 输出变更摘要（哪些条款变了、哪些权利变了、哪些数字变了）；
- 为新版本生成唯一摘要哈希并可锚定到 Monad。

### 6. 风险状态管理（跨模块能力）

每个项目维护一个动态风险状态：

```text
HEALTHY          # 披露及时、解锁可控、运营正常
NEEDS_REVIEW     # 有更新待核实、出现不一致
HIGH_RISK        # 重大解锁、长期不披露、负面信号
```

状态由以下因素综合产生：
- 项目方披露是否及时；
- 代币解锁压力（近期大额解锁触发升级）；
- 经营/产品进展（路线图偏差触发降级）；
- 市场异常波动（与基本面脱钩触发升级）；
- 社区负面信息浓度；
- 资料缺失或前后冲突；
- 重大事件和新闻。

**状态变更时生成新证明摘要 + 锚定 Monad + 通知关注用户**。

### 7. Monad 链上存证（跨模块能力）

锚定对象（每次生成哈希并上链）：

| 触发场景 | 上链内容 |
|---|---|
| 项目方披露新版本 | `project_id`, `document_version`, `evidence_hash`, `doc_type`, `created_at` |
| 研究报告 | `report_id`, `project_id`, `doc_version`, `risk_status`, `evidence_hash`, `created_at` |
| 风险状态变更 | `project_id`, `from_status`, `to_status`, `reason_hash`, `created_at` |
| 投资者问答 | `question_hash`, `answer_hash`, `cited_doc_versions[]`, `risk_level` |
| 项目方内容发布 | `content_id`, `content_type`, `project_id`, `content_hash` |
| 用户授权执行 | `user_consent_id`, `platform`, `action_type`, `evidence_hash` |

链上不保存：白皮书原文、用户个人信息、完整市场数据、聊天记录全文。

**用户可验证**：
- 这份报告是否生成过；
- 对应哪个资料版本；
- 结论生成的时间；
- 当时项目风险状态；
- 后续资料是否发生变化。

## 五、Monad 的必要性

TokenTruth 不是把 AI 聊天记录写入区块链。

Monad 在这里承担 **"持续可验证的披露 + 研究 + 状态历史"** 的可信层：

1. **披露版本可追溯**：项目方修改白皮书/代币规则后，新旧版本哈希都上链，投资者可验证"我看到的是哪一版"；
2. **研究报告可复核**：每个 AI 结论绑定"何时生成、依据哪个资料版本、当时风险状态"，事后可复盘；
3. **风险变化有据**：风险状态从 HEALTHY → NEEDS_REVIEW → HIGH_RISK 的每次迁移都上链，争议时作为客观证据；
4. **事件流是天然并行的**：多个项目、多个用户、多个问答的存证请求天然独立——这正是 Monad 并行 EVM + 高 TPS 的优势场景；
5. **监管/审计友好**：第三方可通过链上哈希验证研究结论与披露版本，无需读取完整文档。

设计理念：

> **AI 负责理解与分析，非小号提供市场与项目数据，Monad 负责保存可验证的研究证据和状态变化。**

## 六、黑客松 MVP（48 小时）

第一版只实现**一个项目**的完整闭环，重点展示"问得明白 + 讲得清楚"两条主线。

### 6.1 MVP 范围

- **项目**：选用一个真实加密项目（候选：Monad 生态项目、Top 100 代币），完整导入其白皮书、代币经济、解锁计划、官方公告；
- **数据源**：项目资料（公开）+ 行情（公开 API 或非小号提供的快照）+ 社区帖子（X/Discord 抓取或种子数据）；
- **不接入**：真实交易平台（仅留 mock 授权 UI）、真实资金流、第三方 KYC。

### 6.2 MVP 流程

#### A. 投资者侧
1. 打开 `/` 项目目录 → 选择一个项目；
2. 打开 `/chat` → 输入 "这家公司靠什么赚钱？"；
3. 看到答案（结论 + 引用 + 时间 + 风险等级）；
4. 打开 `/track` → 把该项目加入关注列表，设定跟踪周期；
5. 系统生成一条研究摘要 → 计算 `evidence_hash` → 写入 Monad Testnet；
6. 打开 `/proof?hash=0x...` → 看到链上存证详情 + Monad Explorer 链接。

#### B. 项目方侧
1. 打开 `/company` → 项目方仪表盘（演示用 mock 身份）；
2. 上传一份白皮书 v2 → 系统自动与 v1 对比 → 输出 diff 摘要；
3. 点击"生成介绍材料" → 系统基于新版本生成 3 段式介绍 + 1 个视频脚本；
4. 点击"答投资者问" → 系统基于知识库自动回复 5 个常见问题；
5. 所有动作生成版本/内容哈希 → 写入 Monad Testnet。

#### C. 现场 Demo 三个问题
```text
Q1：这个项目靠什么赚钱？
Q2：代币持有人有什么权利？
Q3：未来三个月有哪些解锁风险？
```
每个问题展示：AI 结论、引用资料、信息时间、风险等级、链上存证交易哈希。

#### D. 版本变化 Demo
- 修改一项代币规则（演示用：调低某月解锁比例）；
- 系统输出变更摘要 + 新版本哈希；
- 对比新旧两个版本的 `evidence_hash`；
- 投资者页面立即反映新版本。

### 6.3 验收口径

- 4 个页面 200（`/`、`/chat`、`/track`、`/company`）；
- 3 个问题都能返回带引用的答案；
- 至少 3 次链上写入（研究报告 + 披露更新 + 状态变更）；
- `/proof?hash=...` 能查到完整链上记录；
- `npm run demo` 输出 `status: passed`；
- 单元测试 + smoke 全绿。

## 八、暂不包含的功能（明确边界）

第一版**不做**：

- ❌ 自动买币/卖币（任何未经用户实时确认的自动下单）；
- ❌ 自动替用户做投资决策（不输出"该买/该卖"指令）；
- ❌ 真实资金托管、钱包私钥管理；
- ❌ 绕过平台 KYC/合规的暗仓交易；
- ❌ 复杂社交交易、跟单社区；
- ❌ 完整的证券级投资顾问系统（无牌不做）；
- ❌ 做市、刷量、操纵市场的任何工具；
- ❌ 医疗/法律/税务建议（不跨界）。

第一版**明确做**：

> 信息理解、证据追踪、风险解释、链上存证、用户授权后的可追溯执行。

## 十、项目价值

### 对投资者
> 让投资者更快理解项目、更清楚信息来源与风险依据，避免被错误信息误导。

### 对项目方
> 让项目方可以持续、统一、可验证地向市场披露信息，降低沟通成本、减少口径不一致带来的争议。

### 对数据/平台方
> 在现有行情与项目数据基础上增加 AI 理解、项目尽调、链上可信记录能力，提升用户停留时长与数据复用价值。

### 对 Monad 生态
> 将项目资料、研究结论、风险状态、披露版本变成持续产生、可验证、可追踪的链上证据，展示"AI 时代的内容信任"。

### 对监管/审计
> 提供一种"AI 投研可被监管/可被复核"的技术路径，缓解当前 AI 投研"无法验证"的行业问题。
